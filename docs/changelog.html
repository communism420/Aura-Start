Aura Start 2.1.0

Changes since 2.0.5: shared synchronization, compatible settings upgrades, complete ZIP backups, and Countdown with a customizable completion signal. These are the changes introduced in 2.1.0.

  • Added optional Countdown with a 1-second to 24-hour duration, pause/resume/reset, volume control, and a built-in or custom completion signal.
  • Added local audio preparation for many formats, including WAV, MP3, Ogg, FLAC, AAC, AIFF, and WMA, with a packaged decoder fallback. Original files up to 20 MiB are retained alongside a portable WAV signal from their first 60 seconds.
  • Synced timer preferences and the selected original audio plus playback copy through Google Drive, including while the widget is hidden. The running countdown stays local across this profile's tabs and reloads; keep the widget enabled and an Aura Start page open for its signal.
  • Replaced upload-only backups with bidirectional Google Drive synchronization and deterministic merging across connected devices. Changes to different fields merge independently; deletion records prevent old snapshots from restoring removed links.
  • Added quiet checks about every five seconds while Aura Start is visible and online, and about once a minute with pages hidden or closed while the browser runs. Multiple pages share the same checks. Unchanged verified revisions skip data/media transfers, uploads, animation, and last-sync-time writes. Opening, closing, focusing, or showing a page does not itself trigger sync.
  • Consolidated synchronization into one shared aura-start-sync.json in normal Drive. Conditional writes reject stale revisions and retry after merging concurrent edits. Migration verifies the merged data and selected media in a new shared file before conditionally deleting covered older copies, including accessible hidden backups. Simultaneous first connections can briefly create duplicates; later sync converges on one file. All installations must use the latest 2.1.0 build.
  • Added alarms for connected background sync. Native Chrome uses drive.file for the shared file alongside drive.appdata for legacy hidden backups, so upgrading from 2.0.5 may require reconnection. Device OAuth keeps drive.file; full Drive access is never requested. Media processing and ZIP backups need no additional permission.
  • Added settings migration that fills new options without resetting existing choices. Fields missing from older cloud snapshots, JSON backups, or Restore Points do not erase newer preferences.
  • Added shared Markdown notes, including edits, clearing, hidden-widget sync, and ZIP/JSON backups. Existing local notes migrate only after the main document and a recovery point are saved.
  • Synced Save open tabs and delete-backup-on-disconnect preferences while retaining actual browser permissions, connection state, running timers, and Restore Timeline locally. Concurrent note edits resolve consistently with previous local text protected by recovery points.
  • Added custom background image synchronization and careful migration of images already saved in 2.0.5.
  • Added Full Backup ZIP with settings, links, notes, Restore Points, and current/historical background files. ZIP v2 includes only the selected original Countdown audio, with no playback WAV or other historical sounds; built-in selection includes no audio. Import rebuilds playback locally, preserves the Drive connection, and accepts older v1 ZIPs and portable JSON.
  • Renamed JSON-only export to Settings and links only (JSON). It excludes media bytes and omits custom-file references and active Custom background selections neutrally. Explicit built-in choices and intentional removals remain applicable settings. Older portable JSON files with embedded media remain importable.
  • Made confirmed Drive deletion pause sync, permanently remove matching normal-Drive snapshots including old 2.0.5 files, renamed files and copies in Trash, and verify their absence before clearing this installation's credentials. Hidden legacy backups are included only when already authorized. The current Device OAuth configuration requests only drive.file; a persistent notice explains when hidden data could not be checked. Failure retains a paused account for retry; local data and media remain intact. Stale actions cannot clear a replacement connection, and updated peers pause when an established cloud copy disappears.
  • Hardened authorization recovery with a persisted sign-in flow, bounded silent renewal and retries, and guards against delayed authorization after disconnect. Confirmed invalid grants still require explicit reconnection.
  • Made disconnect local to this installation instead of revoking authorization across all browsers. Manual disconnect stops sync and clears saved credentials; automatic recovery cannot reconnect it.
  • Fixed the Google Drive completion message after restoring on a new installation. Existing cloud data now reports successful synchronization; the first-copy message appears only when Aura Start's cloud storage was empty.
  • Preserved 2.0.5 JSON import compatibility. Old exports did not contain Notes widget text or the actual background image; those migrate from an existing local installation. Import cannot recover content absent from the backup.
  • Improved import, Restore Point restore, and Undo to preserve the current Drive connection and unrelated synchronized edits.

Aura Start 2.0.1–2.0.5

Earlier maintenance releases fixed group ordering, browser-specific manifests, Firefox authorization, and release packaging. Version 2.0.5 moved automatic uploads into the extension background context, added token recovery and pending upload retries, and preserved credentials during temporary failures. The 2.1.0 changes above add bidirectional shared synchronization to that foundation. See the repository changelog for the detailed historical entries.

Aura Start 2.0.0

Migration, personalization, Firefox, and data ownership release. This release focuses on nested organization, safer recovery, optional customization, cross-browser packaging, and keyboard-friendly workflows.

Highlights

  • Added nested groups up to two levels, including parent selection and drag-and-drop reparenting.
  • Added Fuse.js-powered fuzzy search across title, URL, description, and tags, with result counts and quick filters.
  • Reworked restore points into a searchable Restore Timeline with day grouping, action filters, export, and confirmed restore.
  • Added optional Save open tabs workflow with runtime tabs permission, preview, duplicate filtering, and restore point protection.
  • Added built-in and custom local background images with blur, dim, and positioning controls.
  • Added optional widgets for header clock, local Markdown notes, and a Pomodoro timer.
  • Added Firefox-oriented build support with WebExtension API wrappers and Device OAuth fallback for Google Drive sync.
  • Added stronger A Fine Start migration flow with safer import preview and compatibility notes.
  • Added first-run onboarding, empty state actions, demo data, and Google Drive restore during setup.
  • Added Export / Backup hub, Command Palette, Duplicate Finder, and Privacy Promise.
  • Fixed Google Drive sync behavior across test and Chrome Web Store builds, including OAuth flow, reconnect states, token persistence, and automatic backup handling (I hope).
  • Kept Google Drive sync optional, with native Google Chrome using hidden appDataFolder storage and Firefox/compatible Chromium fallback builds using Drive file access only for Aura Start's own sync file.
  • Improved keyboard shortcuts, Cyrillic-layout shortcut handling, search focus behavior, and Command Palette access.
  • Improved destructive-action safety with restore points, confirmations, and clearer recovery messaging.
  • Updated translations across all supported languages and fixed untranslated UI labels.
  • Redesigned the documentation website and refreshed privacy, store listing, and release materials.
  • Updated screenshots to match the new Aura Start design.

Documentation

The user documentation now includes migration and comparison guides, privacy information, screenshots, and clearer explanations of export and recovery.
